### 1. typing 和 Pydantic 的区别是什么？ 
```
typing：
    1. 静态类型注解系统，让代码“可描述、可被IDE理解”。
    2. 解释器运行时不会强制，只是元数据。
Pydantic：
    1. 运行时数据校验 + 解析库。
    2. 它读取typing注解，在对象创建时真正校验和转换外部数据，失败抛ValidationError。
关系：Pydantic建立在typing之上，用typing语法声明类型，Pydantic在运行进执行这些类型结束。
```

### 2. 为什么 Python 写了 int 类型提示，运行时仍可能收到 str？ 
```
Python的类型提示不是运行时强制约束，只是给人和工具看的“注释”。
解释器在执行时不会检查它们。
```

### 3. dataclass 和 Pydantic BaseModel 分别适合什么场景？ 
```
dataclass：
1. 轻量领域对象 / 内部数据结构
2. 本身主要负责“承载数据”
3. 不负责强运行时校验

Pydantic BaseModel：
1. 数据边界模型
2、运行时校验、解析、序列化
3、特别适合 API、配置、LLM输出、Tool参数

```

### 4. 为什么 dataclass 的 list 字段常用 default_factory=list？ 
```
可变对象不能作为共享默认状态；
default_factory=list可以让每个实例创建时都调用一次list()，得到独立的空列表；
```

### 5. ValidationError 和你自定义业务异常有什么区别？ 
```
ValidationError：表示输入的数据不合法
自定义业务异常：表示业务规则不允许
```

### 6. 为什么不能所有错误都 return None？ 
```
None可能表示没找到、本来就没值；
异常可能表示输入非法、业务禁止、依赖服务失败、系统异常；
全部用None表示就没办法区分这些不同的情况了。
```

### 7. pytest 相比手工 print 测试解决了什么问题？ 
```
pytest把测试从人工操作变成可自动执行、可重复、可集成的工程实践；
print只能让自己看到结果；
pytest能让程序自动判断结果是否符合预期。
```

### 8. 如果 LLM Tool 需要参数 user_id:int，Pydantic 在其中可能起什么作用？
```
充当“不可信输入 -> 可信Python对象”的边界层；

当LLM产生{"user_id": "123"}，由Pydantic解析/校验，合法，执行Tool
当LLM产生{"user_id": "abc"}，由Pydantic解析/校验，不合法，调用失败
```
